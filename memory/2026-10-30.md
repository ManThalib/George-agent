### Failure breaker implemented (`common/circuit_breaker.py`)

The rails have always said "3 consecutive failures → self-pause, critical
alert"; nothing counted failures. Now:

- only execution failures count (rejections/queued/dry-run are neutral);
- a successful execution clears both streaks;
- three failures (or five consecutive RPC errors) set a sticky pause and raise
  `SELF-PAUSE …` with count, rail, signal, stage and error;
- `run_once` processes nothing while paused and stops **mid-batch** when the
  third failure lands, leaving the rest pending;
- `--once` exits **76** (distinct from 75 KILL and 1 failed cycle);
- `--resume` is the only way out, and it raises no rail.

Note: RPC errors are a subset of failures, so with the shipped 3/5 values the
failure rail trips first; `pause_on_rpc_error_streak` only bites when configured
below the failure cap. Documented rather than silently reordered.
